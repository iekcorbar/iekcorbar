💡 How to Use This Manual

Everything in this manual describes what the Iekcorbar website actually does, verified directly against its code — not a generic moderation policy template. §2 is the one section that's general guidance rather than a description of a real feature; it's labelled as such. Confidential, staff use only.

§ 1 — Part I: Getting Access
Staff Roles & What Each Can Do

Every account on the website has exactly one role stored against it: Player, Moderator, or Admin. There is no larger hierarchy underneath that — these three roles are the whole system.

Admin
⚙ Admin
Full access to every Staff Panel tab, including Settings.
  • Everything a Moderator can do
  • Full Settings tab (all sub-tabs)
  • Change any other account's role
  • Edit Site Content (role display names, page titles)
Moderator
🛡 Moderator
Full day-to-day enforcement access, no site configuration.
  • Kick / ban / temp-ban / unban / staff notes
  • Reports Inbox & Bug Reports
  • Wiki, Updates, Polls, Events tabs
  • Settings tab is visible but shows nothing
Player
👤 Player
Ordinary registered account — the default for everyone.
  • No Staff Panel access at all
  • Visiting /moderation shows an access-denied message

How a Role Actually Gets Changed

There is no self-service way to become staff. An existing Admin changes another account's role from the Clearance Role dropdown in the Crew & Sanctions tab (see §5) — that's the only mechanism. An Admin cannot change their own role from that dropdown; their own row shows "Owner (Protected)" instead.

ℹ️ Two-Factor Authentication Is Automatic

The moment an account's role is set to Moderator or Admin, that account is required to set up 2FA the next time it logs in — there's no separate step to turn it on. See §3.

§ 2 — Part I: Getting Access
General Staff Conduct
⚠ This Section Is Guidance, Not a Fixed Rulebook

Unlike the rest of this manual, the points below aren't a description of something the website enforces — they're general good practice. Adapt them to how your own team actually operates; don't treat the wording as official policy with specific mandated timings.

  • Stay impartial. Treat friends and strangers the same way when reviewing a report or issuing a sanction.
  • Write real reasons. Every kick/ban/tempban reason you type is logged and can be shown to the player — write it as if they'll read it back to you.
  • Recuse yourself when conflicted. If a report involves someone you know personally, let another staff member handle it.
  • Keep player data private. Bug reports and reports both reveal information (bug reports show the reporter's identity) — don't share it outside the staff team.
  • Ask before a permanent action if you're unsure. A ban is easy to issue and awkward to reverse; a second opinion costs nothing.
🚫 Misuse of Sanctions

Kick/ban/tempban dispatch a real, live in-game command the moment you submit them (§5). Treat that with the same seriousness as if you were typing the command directly into the server console yourself.

§ 3 — Part I: Getting Access
Logging In & Two-Factor Authentication

Moderator and Admin accounts are protected by real Two-Factor Authentication (2FA) on top of the normal password. This is mandatory and cannot be turned off per-account.

First-Time Setup (once per staff account)

  1. Log in as normalEnter your email and password on the website as usual.
  2. Scan the QR codeBecause your account is Moderator or Admin, you'll see a QR code instead of being logged straight in. Open an authenticator app — Google Authenticator or Authy both work — and scan it. Can't scan? Use the manual entry code shown underneath instead.
  3. Confirm with a codeYour authenticator app now shows a fresh 6-digit code every 30 seconds. Type the current code into the website to finish setup. That app is now permanently linked to your account.

Every Login After That

Enter your email and password, then enter the current 6-digit code from your authenticator app when prompted. No QR code appears again unless another Admin resets your 2FA.

⚠ Lost Your Authenticator App?

There is currently no self-service reset. Contact another Admin directly (not over public Discord) to have your account's 2FA cleared so you can set it up again on a new device.

ℹ️ "Not Authenticated" Errors After a Site Update

The Staff Panel and several other features (Friends, Journal, Bug Reports, Site Content) check a real, secure session — not just whatever your browser happens to remember. If you were already logged in before an update and suddenly see "Not authenticated" errors, simply log out and log back in (2FA included, if you're staff). That refreshes your session and resolves it every time.

§ 5 — Part II: The Staff Panel
Crew & Sanctions
⚠ These Actions Are Real, Not Simulated

Kick, Ban, Temp-Ban and Unban dispatch a live in-game command the instant you submit — over RCON, straight to the server's CMI plugin (cmi kick / cmi ban / cmi tempban [player] 7d [reason] / cmi unban). There is no preview or separate "apply" step. If the Minecraft server can't be reached, the panel shows an error and applies/logs nothing — safe to just try again.

Issue Penalty Form

  • Target In-Game Name (IGN) — exact Minecraft username.
  • Sanction Action — Kick (eject now), Ban (permanent), Tempban (fixed 7-day duration, not adjustable per case), Unban, or Staff Note (record only, no in-game command sent).
  • Violation Reason — required, logged, and visible in the transmission log below.
ℹ️ Staff Are Protected

Kick/ban/tempban against another Moderator or Admin account is blocked by the panel itself — it never even reaches the game server.

Registered Members Table

Below the form: every account, with columns Player Skin, Email Address, IGN, Clearance Role, Sanction Commands. The Clearance Role dropdown is only editable by Admins (Moderators see it as plain text); an Admin's own row reads "Owner (Protected)" instead of a dropdown. Each row also has quick-action buttons — Note and Unban are always available, Kick / Tempban / Ban only appear for non-staff accounts.

§ 6 — Part II: The Staff Panel
Reports Inbox

Any player can submit a report against another player from that player's profile page — category, target username, and a details field. Reporter identity is never stored anywhere, including in the database, so there is no way to see who submitted a given report.

Handling a Report

  1. Review itNewest reports appear first, with category, target, timestamp and the reporter's written details.
  2. Act directly from the cardKick and Ban buttons are right on each report, alongside a Message link to open a chat with the reported player.
  3. Dismiss when doneRemoves it from the inbox. There's no separate "resolved" vs "denied" state to set — dismissing is the only outcome the panel tracks.
💡 Best Practice

Check the Reports Inbox at the start of every session — a quick pass through it is one of the most visible things staff do for community trust.

§ 7 — Part II: The Staff Panel
Bug Reports

Separate from the Reports Inbox. Any logged-in player can submit a website bug report from their own profile page — a subject and a description. Unlike player reports, the reporter's identity is included (username and email), so you can follow up and ask for reproduction steps.

Working a Bug Report

  • Mark each one Open, Fixed, or Won't Fix as you triage it.
  • Delete a report once it's fully dealt with, if you want it off the list.
🚫 Marking "Fixed" Announces Nothing

Changing status here is purely internal bookkeeping — it does not post anything to the public Updates feed. If a fix is worth telling players about, add an entry yourself in Updates Manager (§8) once it's actually shipped.

ℹ️ Email Copy

Reports are also emailed to bugs@iekcorbar.com when that mailbox is fully configured. The Staff Panel is always the source of truth regardless — check it directly rather than relying on the inbox.

§ 8 — Part II: The Staff Panel
Content Tabs

Four tabs manage public-facing content directly — changes go live immediately, there's no draft/preview step.

Wiki Lore

Create, edit, and delete the articles shown on the public /wiki page — races, jobs, brewing, lands, and anything else worth documenting for players.

Updates Manager

Post entries to the public Updates / changelog feed. This is the right place to announce a shipped fix or new feature — nothing else on the site posts here automatically.

Polls Manager

Create community polls and review how players are voting.

Events Manager

Create and edit community events shown on /events, which players can register interest in directly on the site.

💡 Brewing Recipes & Blueprints

The /brewing page itself (not the Staff Panel) has its own "New Recipe" / "New Blueprint" buttons for Moderators and Admins — there's no separate manager tab for it.

§ 9 — Part II: The Staff Panel
Settings (Admin Only)

Settings is split into sub-tabs, all Admin-only — enforced by a real server-side check, so a Moderator cannot reach these even by other means.

  • General: Java version badge and map URL shown on the homepage.
  • Carousel: Homepage image slideshow items.
  • Starter Guide: The "Getting Started" steps on the homepage. Each step can have an image or PDF attached, up to 20MB — useful for a downloadable player manual.
  • Rules Manager: The public /rules page content.
  • Vote Sites: Voting-site links and reward configuration.
  • Projects Manager: Community build projects players can sign up for.
  • Site Content: Rename how roles display across the whole site (e.g. if your LuckPerms group names don't match "Admin / Moderator / Player") and a couple of page titles. This only changes the displayed label — it never changes anyone's actual permissions or in-game rank.

§ 10 — Part III: Beyond the Panel
Player-Facing Features to Know

These live on the website but aren't Staff Panel tools — players will ask you about them, so it helps to know how they work.

Profile Journal (Logbook)

Every player has a private diary on their own profile with a page-flip animation — one entry per day, optionally with a photo. Private by default; becomes visible to an accepted Friend automatically, and a player can also explicitly share one specific page with a friend (they get a notification linking straight to it).

Friends System

Accessible from the nav bar. A request is sent by Minecraft username; the other side accepts or declines from their Friends page or the notification bell. Being friends is what unlocks seeing someone's Journal.

Bug Reports (Player Side)

The "Report a Bug" card on a player's own profile is where the Bug Reports tab (§7) gets its content. If a player asks whether their report went through, check that tab for their username/email.

Installing the Site as an App

The website can be installed like a native app on a phone. On Android/Chrome, the browser offers this automatically; on iPhone there's no automatic prompt — players need Share → "Add to Home Screen" instead.
